# Article engagement and social previews

The article detail page now includes persistent likes, comments and share counts. Engagement is stored in Supabase tables: `article_likes`, `article_comments`, and `article_shares`. The corresponding database migration is applied to the D Young Luxury Hair Supabase project.

## Cloudflare social-preview setup

Article Open Graph and Twitter metadata is generated by `worker.ts` for each `/blog/<slug>` request. The worker reads the published article's title, description and `featured_image` from the Supabase REST API using the public anon key.

Before deploying this branch, add the Supabase anon/publishable key as a Cloudflare Worker secret (never use the service-role key):

```bash
npx wrangler secret put SUPABASE_ANON_KEY
```

Paste the D Young Luxury Hair project's public anon/publishable key when prompted, then deploy:

```bash
npm run build
npx wrangler deploy
```

The `SUPABASE_URL` is configured in `wrangler.jsonc`. The anon key is intentionally not committed to Git. The worker intercepts only article detail URLs and lets all other requests continue to the static assets.

## Notes

- A visitor identifier is stored in that browser's local storage to keep a visitor's like state across visits.
- Comments are public and appear immediately after submission. The admin moderation workflow is not part of this change.
- Share counts record successful native share actions or successful link copies. They are interaction counts, not unique reach.
- Social platforms may cache link previews. After deploying, use the platform's link debugger or wait for its cache to refresh when testing a changed preview image.
